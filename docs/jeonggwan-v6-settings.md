## 1. Transit Router 설정

### 문제 상황
- 시뮬레이션 결과에서 **장거리 Walk (10-50km)** 비율이 23.5%까지 증가
- 에이전트들이 PT 대신 Walk를 선택하는 비정상적 패턴 발생

### 원인 분석

| 분석 항목 | 결과 |
|:---|:---|
| 정류장 거리 | 모든 클러스터가 정류장에서 1km 이내 ✅ |
| GTFS 데이터 | 19개 노선, 271개 정류장 포함 ✅ |
| GTFS→MATSim 변환 | 모든 노선 변환 완료, 손실 없음 ✅ |
| **환승 경로** | O1→D2 경로에 **3회 환승 필요** ⚠️ |
| **기본 환승 제한** | MATSim 기본값 = 2회 ❌ |

### 핵심 발견
O1(정관 중심)에서 D2(정관 중심)까지의 PT 경로:
```
182번 → 107번 → 기장군6 → 기장군8
(3회 환승 필요)
```
MATSim의 기본 `maxTransfers=2` 설정으로 인해 이 경로를 탐색하지 못함.

### 적용된 설정

```xml
<module name="transitRouter">
    <!-- 출발/도착지에서 정류장 탐색 반경 (기본 1000m → 2000m) -->
    <param name="searchRadius" value="2000" />
    
    <!-- 탐색 확장 반경 (기본 200m → 500m) -->
    <param name="extensionRadius" value="500" />
    
    <!-- 환승 시 도보 허용 거리 (기본 100m → 500m) -->
    <param name="maxBeelineWalkConnectionDistance" value="500" />
    
    <!-- 직행 도보 비용 계수 -->
    <param name="directWalkFactor" value="1.0" />
    
    <!-- 최대 환승 횟수 (기본 2회 → 5회) -->
    <param name="maxTransfers" value="5" />
</module>
```

### 2.2 수단분담률 추이

| Iteration | Car | PT | Walk | DRT | SAV |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 0 | 68.2% | 31.7% | 0.9% | 0% | 0% |
| 20 | 57.1% | 14.3% | 17.4% | 5.5% | 5.7% |
| 43 | 58.0% | 9.1% | 23.5% | 5.0% | 4.4% |

> Walk 비율이 지속적으로 증가하는 패턴 = PT 경로를 찾지 못해 Walk로 대체됨

### 2.3 PT vs Walk 효용 비교 (20km 통행 기준)

| 수단 | 소요시간 | 효용점수 |
|:---:|:---:|:---:|
| Walk | 400분 | -42.0 |
| PT | 76분 | -10.1 |
| Car | 33분 | -10.8 |

> PT가 Walk보다 4배 높은 점수를 받지만, 경로를 못 찾으면 효용 = -∞
